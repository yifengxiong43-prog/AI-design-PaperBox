纸盒包装创意工作台 V1.0.0

双击“纸盒包装创意工作台.exe”打开原生 Windows 软件窗口。
Windows 10/11 + .NET Framework 4.8，无需浏览器或额外服务器。
请保留同目录的 packbox 与 python-tools 文件夹，它们包含模板和尺寸核算运行时，无需另装 Node 或 Python。

使用
1. 左侧最上方产品参数始终展开。笔类、支数、完整笔长、直径为必填，长度单位mm。
   酒精笔和彩铅可横放或竖放；丙烯笔必须竖直收纳。
2. 填写设计需求，在包装尺寸中选择档位与每边预留3/4/5cm。
   三边各减选定余量；界面仅保留小号标准与大号标准，不自动推荐。
   上限仅用于闭合后的最终包装外径；展开后可以超出，另列占地。仅在需求明确规定时另外限制展开尺寸。
   最长/次长/最短边是排序比较，不是固定宽/深/高；竖笔高度不必对应最短边。
   小号标准短边19.05mm不足预留30–50mm，会提示不可用。
3. reference可添加最多6张当前产品/风格图片。内置资料和品牌参考自动参与生成。
4. 右上角设置文字、图片API地址、具体模型ID和密钥，然后点击“生成设计”。
   没有本地生成模式。正文和图片均使用用户配置的API。
5. 选中方向查看大图；右侧理念、结构、开合、内部排列、创意、计算尺寸等可分别收起。
   底部“视图”切换整体、打开、内部布局、设计草图；更多菜单生成当前视图。
6. 底部输入修改要求，沿用选中版本参数，保留旧版本。要改变支数、笔长、直径等硬参数，
   请修改左侧后重新生成。表单草稿与已生成方案参数独立保存。
7. 顶部保存.paperstudio，保存需求、全部版本、图片、附件和计算数据；项目按钮打开。
   导出支持TXT、JSON、原始分辨率PNG和打样沟通资料包ZIP，打印支持Microsoft Print to PDF。
   ZIP含尺寸表、部件表、材料来源、需求落实、已接受图片与程序尺寸参考；供白样沟通，不是生产刀模。
   没有自动保存，也不自动跨项目学习。
8. 生成期间可点击变色龙跑道，空格跳跃，右方向键→发射Ohuhu马克笔（冷却2.8秒）。
   下方向键↓举盾弹反：持续0.45秒，冷却1.4秒，按住不自动续盾。
   大型冲浪板和椰树高于跳跃极限，必须用马克笔或弹回的导弹击破。
   大型障碍进入视野后会发射一次导弹，成功弹反可反击发射它的障碍。
   变色龙朝右，滑行时蹬地、身体起伏、尾巴摆动、滑轮转动；跳跃收脚和滑板倾斜，落地屈膝缓冲。
   动作随游戏计时推进；失焦暂停、碰撞停止、重新开始复位，不额外调用API。
   大型障碍间距考虑攻击冷却，避免武器未就绪就撞上。
   马克笔命中清除障碍，除过关25分外额外加50分；空中发射可能从障碍上方飞过。
   碰撞后空格重来，Esc退出键盘操作。
   右上显示得分与本次运行最佳分；随机扶桑花、鸡蛋花、竹子、小恐龙、热带叶片、菠萝、冲浪板和椰树。
   初始速度480px/s，每清除/越过一个障碍加速32px/s，最高880px/s。
   小游戏不影响生成，离开窗口暂停、生成结束停止；右上仍可取消任务。

计算规则
整排净宽 = 支数×笔径 + 整排总余量 + (支数−1)×(单间隙+隔板厚度)。
例如12支、15mm直径、整排总余量4mm、无隔板和额外单间隙：净宽184mm。
4mm不是每一个间隙都加4mm；模型可选择其他余量，但必须说明理由。
单元外宽另加两侧壁厚，单元长边为完整笔长+装取余量+两端壁厚。
盒体按单元包络、内部配件预算、两侧装配间隙、独立壳厚与外突预算计算；外包装预留再单独检查。
部件区分平片尺寸和闭合安装尺寸；笔组展开与含支撑/盖板的整体展开范围分别列出。
所有分组支数之和必须等于输入；每组单排。6×2应拆成两组6支，展开互不遮挡。
闭合时单元不能相交；展开时竖笔按正面投影、横笔按顶面投影检查全部笔身可见。
以中心为原点的负坐标会按闭合/展开状态分别整体平移，相对排列不变；不把负坐标直接判成结构错误。
位置必须完整给出X/Y/Z；缺失时携带具体字段和失败方案修正，不凭空补0。
程序重算尺寸与内部排列文字，附逐组尺寸账本及按毫米绘制的笔身参考图交给图片模型。
盖板、连接片等附属部件尺寸是模型设计选值，逐件标注，不属于实测结果。
尺寸余量、壁厚、隔板是设计假设，不是已有库存测量；铰链、承载、运动路径与装配需打样。
轴对齐包围盒与投影检查不能证明复杂机构一定可制造，不提供工程刀模或可交互3D。

需求与图片质量
每次文字规划自动读取内置 packaging-designer Skill 与《纸盒包装设计方法》，先理解资料，再设计、计算和复核，通过后才出图。
理解阶段逐条保留原文，区分禁止、保留、修改和偏好；后续修改替代旧要求时留下记录。
V0.8.2由程序保存原始条目与编号，不依赖模型重复抄写。模型漏返、合并或重新编号时，
保留所有原文；不能对齐的解释会明确标记，仍需后续设计与独立复核逐条通过，不假装已理解。
材料名必须匹配原表名称列，来源摘录必须存在；引用覆盖材料、案例、历史问题和测试要求。
每条资料使用持久UUID引用ID；原文件名/工作表/行号仅作位置追溯。模型只可选用本轮实际检索的记录，摘录须与原文逐字一致。
引用失败会从现有原文重新建立检索，并让模型核对一次。确认是非关键案例但仍不可用时，删除该引用和应用说明，继续设计并提示。
材料、工艺、风险、测试及身份不明的来源仍严格核验；恢复后仍缺关键依据会暂停，并标注结论尚未验证。
预分析索引过期或损坏时，改用原文临时索引；不使用失效摘要、规则或图片分析。重启后重新检查内置资源。
详细引用日志在 %LOCALAPPDATA%\PaperStudio\reference-errors.jsonl，包含错误类型、编号、失败摘录、对应原文和允许引用清单，不含API密钥或图片。
可折叠的“上次需求理解”“制造与打样”“资料依据”可查看这些结果，随项目保存。
方案未通过时带着具体问题修正，每次点击最多4轮草案（初稿+3次修正）；保留通过方向，只修失败方向。
相同错误无进展时提前停止。理解、候选和问题自动保存在本机最近一次规划检查点，不包含密钥。
复核中断后保持相同输入再次点击生成，可接着复核，不重复已完成的理解与草案；改需求或附件则重新开始。
检查点不是项目自动保存，图片和已完成项目仍需手动保存。
保留自然语言细节与历次修改，拆分成逐条要求；每个方向必须返回具体落实说明。
仅改名称/配色不构成三个结构方向，完全重复的结构与开合会被拦截。
整体图要求展示同一结构的闭合与全部展开，草图沿用相同单元、编号和尺寸账本。
每张新方案图片返回后通过文字视觉模型复核数量、遮挡、比例、结构与需求落实；
草图逐单元、逐部件核对外宽/深/高标注，并附原始透明草图参考与程序尺寸引线图。
只统计主展开视图内的完整笔身，不累加不同视图重复出现的笔。请求真正的透明PNG背景，非透明纸盒。
程序检查PNG透明通道、边缘与非空线条；视觉复核另查画出来的棋盘格或背景底板，不能只凭有透明边缘就通过。
预览底色不写入导出文件，视觉复核使用白底副本，原始透明图保持不变。
图片返回后复核中断，保留待复核图；点击“继续复核已有图片”只重新检查，不重复出图。
明确不合格时保留问题，点击“按检查意见重新生成”才再次调用图片API；原有合格图在新图通过前保留。
待复核图随项目保存，关闭前请手动保存；没有自动保存。待复核图不进入打样资料包。
视觉复核依赖模型，可能误判或漏判，不能保证像素级正确。最终仍须人工核对和实物打样。
旧版项目仍可查看；若需新分组计算与复核流程，应重新生成或基于旧版生成新版。

Packbox 模板工具
右上角“导出”→“Packbox · 模板展开图”，选择盒型、调整L/W/H毫米尺寸，导出ZIP。
有方案时带入当前方案外径；这是可修改的模板起点，不是自动把复杂方案转换成精确刀模。
ZIP含红裁切线/绿折线SVG、可在Packbox Studio打开的.pbox、实际参数和MIT许可。
Packbox为零板厚几何，纸厚、内托和装配需另行补偿；自锁底未建完整咬合槽，天地盖需分别导出底与盖并留配合间隙。
用于白样讨论，不能直接视为已验证的生产刀模。此版本未内嵌Packbox完整编辑器或3D预览。

API与调用次数
基础地址通常含/v1，不能用/keys或/dashboard。文字模型支持Chat Completions、图片输入、JSON输出；
图片模型支持Images generations/edits、多图输入与data[0].b64_json。保留gpt-image-2及自填模型。
图片服务生成草图需支持background=transparent及output_format=png；不支持时会明确失败。
新方案正常流程：3次文字规划（理解、设计、复核）+ 3次图片生成 + 3次文字视觉复核。
若引用校验失败，最多追加1次引用纠正请求；已有参数可回答的澄清问题最多追加1次核对，正常流程不增加调用。
修改通常3次文字规划 + 1次图片 + 1次视觉复核；补充视图1次图片+1次复核。
最多3次方案修正，每次最多追加设计与复核2次文字调用；网络与图片失败不自动重试。
默认流式接收文字，收到内容后显示接收进度。服务商不支持时可在设置中关闭“流式接收文字”，
此选择会保存；切换后需手动重新发起，不会自动重发可能已计费的请求。
文字识图使用压缩副本，不放大原图；图片生成、保存及导出的原图与透明通道不变。
单次文字请求最多等8分钟，图片12分钟，模型列表45秒，均可主动取消。
超时会注明当前阶段，并区分客户端等待超时与服务商408/504/524超时。
超时或连接中断后停止后续方向的图片调用，保留已完成方案；不自动重发，服务商可能仍在处理原请求。
连接失败时保存安全诊断：%LOCALAPPDATA%\PaperStudio\last-api-diagnostic.txt。
仅记录阶段、接口路径、请求体积、用时与错误类型，不记录密钥、需求正文、图片或原始响应。
客户端不能延长服务商网关的超时限制；若服务商持续超时，请稍后重试或换用更快的模型。
草图按需生成。不合格图片也可能产生服务商费用。
基础白盒接入测试只验证图片接口，不含项目资料和正式设计复核。
设置中保存的密钥由 Windows 当前用户 DPAPI 加密，写入 %LOCALAPPDATA%\PaperStudio\api-credentials.dat；也可由 PAPER_TEXT_API_KEY/PAPER_IMAGE_API_KEY 环境变量覆盖。
地址和模型保存在 %LOCALAPPDATA%\PaperStudio\api-settings.json；密钥不写入配置、项目或 EXE。其他 Windows 用户不能解密本用户保存的密钥。
