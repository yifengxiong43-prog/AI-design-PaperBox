# 纸盒包装创意工作台 V1.1.0

原生 WPF / C# / .NET Framework 4.8，无浏览器、WebView或后端服务。Packbox 模板工具随包附独立 Node 运行时，几何复核工具随包附 Python 3.12.10 运行时；无需用户安装 Node 或 Python。

## 构建与验证

- `./desktop/build.ps1` 从 `desktop/version.txt` 读取版本号，构建到对应的 `output/纸盒包装创意工作台-V<版本号>`；分发时保留整个文件夹及 packbox、python-tools 子目录。
- `./desktop/test.ps1` 运行HTTP请求、配置校验、资料传递和项目保存测试，无真实网络调用。
- `./desktop/test-packbox.ps1 -ApplicationPath 'output/纸盒包装创意工作台-V1.1.0/纸盒包装创意工作台.exe'` 验证实际发布包的原生模板窗口、独立运行时、SVG/pbox导出与失败保护；Packbox内核重建和测试见 `packbox/README.md`。
- `./desktop/build.ps1 -OutputFolder 纸盒包装创意工作台-QA-V1.1.0 -Qa` 构建测试专用软件，再传入 `--render-check <绝对输出目录>` 检查原生窗口、故障恢复及资料图片进入请求。输出截图和passed.txt。

## V1.1.0 稳定性与续生成

每次生成有独立任务 ID；当前任务持久化在 `%LOCALAPPDATA%/PaperStudio/active-generation.json`，被新任务替换时旧快照归档到 `generation-tasks`。中断后重新打开软件可恢复进度、已完成方案和已通过检查的图片。继续生成会核对需求、产品参数、附件、知识库和设计方法的指纹；输入变化则重新规划。超时或断线后服务端状态未知时，不自动重发，用户须确认。文字请求支持流式进度，最多等待 40 分钟、连续 20 分钟无数据则停止；图片最多等待 15 分钟。`api-requests.jsonl` 仅记录请求大小、阶段和耗时，不记录密钥或正文。发布版本由 `version.txt` 统一驱动目录、标题栏和 EXE 文件属性。
V1.0.0 的旧规划检查点可在打开原项目或重填原输入后，通过「继续生成」尝试导入；旧版未保存完整表单，无法自动还原需求与产品参数。只有后端确认检查点指纹一致时才复用结果，否则重新规划。
- QA使用独立DesktopQa.cs模拟HTTP响应；正式构建不含此文件，也不含本地生成器。
- `python desktop/build_knowledge_analysis.py`确定性重建分析；加`--check`只校验、不写文件。构建和测试自动运行`verify-knowledge.ps1`，拒绝来源`InputHashes`或图片哈希已过期的缓存。

## V1.0.0 Packaging Design Agent

单主 Agent 通过程序工具编排资料检索、自然语言及 reference 图片理解、方案草拟、几何计算、制造引用核验、独立复核、出图和图片检查。模型提出候选，客户端保留尺寸、引用和图片质量的最终校验权。OpenAI Agents SDK 的工具、校验、会话和追踪思想用于架构参考；当前原生客户端没有直接嵌入该 Python SDK。

`python-tools/geometry.py` 使用 Python `decimal` 独立复核每组完整笔长、单排宽度、三轴尺寸和总支数。完整外壳、连接与展开包络由 `AssemblyGeometry` 计算校验。Python 复核失败会阻止出图；二者都不能代替打样或合规实测。

每次任务的工具调用、检索命中、失败和重试写入 `%LOCALAPPDATA%/PaperStudio/agent-runs.jsonl`，资料错误仍写入 `reference-errors.jsonl`。不保存 API 密钥、图片像素或完整提示词。图片质量修正最多三次请求，已收到但尚未复核的图片可继续复核而不重新出图。项目版本保留原有自然语言修改及方案历史。

## 引用身份、恢复与尺寸作用范围

实际生产日志中的两次引用失败已经定位：模型把“验收方式：白样盒、展开刀线、装配测试”挂到珍珠棉 EPE 记录，实际原文属于“选型与验收/6”；另一次把 `web-hanauma` 稳定 ID 的 `863b` 抄成 `863f`。现在模型仅选择本轮证据短编号，程序原子填入持久 ID、版本哈希和准确原文；错误编号仍严格拒绝。

276条原始/补充记录包含持久UUID `StableId` 和导入内容指纹，旧Id保留位置追溯。重导按精确唯一内容继承身份，改名/移行不变，内容变化或歧义不误绑旧身份。规则见 `source-identity-README.md`。API只需从本轮目录选择短编号，摘要不能用作原文引用。

`CitationGuard`检查实际检索白名单、稳定身份、正文版本和逐字摘录；材料/工艺/风险/测试全部绑定到本轮实际发送的记录。旧项目只带旧Id时可在当前语料内唯一定位，随后绑定稳定身份；不通过相似标题或模糊摘录纠错。稳定身份已存在时不因旧别名重用而改绑另一记录。

引用失败先从当前原文刷新索引并追加一次理解纠正。确认身份的纯创意案例仍失效时，只有材料/风险/合规有效证据齐全才移除失败引用及Application并继续，保存简短未验证提示。身份未知或关键引用失败不能凭路径文字判成非关键，恢复后仍不明则暂停，不删除其校验。理解阶段最多一次引用纠正，网络失败不自动重发。后台追加 `%LOCALAPPDATA%/PaperStudio/reference-errors.jsonl`，记录阶段、失败类型、编号、Quote、对应原文与允许引用清单，不记录API密钥或图片。

`KnowledgeCache.Load`继续严格验证；`LoadOrRefresh`在预分析过期/损坏时只以当前原文重建临时检索，旧摘要、规则与图片分析不再使用。运行中记录增删改与StableId变化会刷新索引。内置原文自身缺失/身份重复不能伪装修复。检查点协议升级并保存已发送的理解来源，资料或稳定ID变动使旧规划失效。

尺寸上限现在明确限定闭合包装外径，展开占地独立；最长/次长/最短不代表固定宽深高。已有规则能回答的追问先追加一次完整理解核对，确实互斥的用户要求仍暂停。36支150×15mm丙烯笔回归确认闭合196×80×185.4mm、展开574mm可以通过407.2/305.6/153.2mm的排序上限；不把185.4高度误比到153.2最短边。

## V0.8.5 几何依据、逐项验收与恢复

`AssemblyGeometry`依据支数、完整笔长和笔径计算每支笔的空间范围；沿笔长轴保留动态装取余量，12×15+4=184mm仍为净宽，壁厚另计。明显超过当前直线轴对齐模型装载边界的输入在调用前拦截。模型只提交Assembly设计参数，程序重算衍生尺寸，不再要求模型重复计算。重复编号、所有unit-wall物料厚度不一致会被拒绝。运动、铰链和外壳真实干涉仍需白样验证。

`AssemblyGuide`输出闭合三视图、完整笔身展开投影和逐部件尺寸引线。相同尺寸可合并标注但列出全部编号；复杂结构附完整尺寸账本，最多4页。草图生成附这些计算依据、匹配的原始透明草图和5张草图联系表；参考总量兼容6张用户附件及已有整体图。程序参考图只承担几何约束，不代替AI创意输出或生产刀模。

`ImageInspection`逐单元检查完整笔身、支数、观察依据；只统计主展开视图，不累加多视图重复笔数。草图再逐单元、逐部件核对宽/深/高引线与账本（0.01mm比较容差），检查细线多视图风格。透明检查拒绝只有白块的空草图。语义检查仍依赖模型，不能代替人工看图或实测。

已返回但复核中断/格式不完整的图片保存在`PendingImages`，手动继续只调用文字视觉复核；明确质量不合格时才在手动重试中带问题重新出图。旧合格图保持到新图通过。项目保存/重开保留待复核图片，没有自动保存，关闭前需保存项目。PNG导出和资料包保存原始字节及alpha，不使用预览缩略图。

新增“导出打样沟通资料包 ZIP”：方案、逐组净/外尺寸、部件尺寸、材料与工艺来源、原始需求及落实、引用证据、已接受视图和尺寸参考。CSV为UTF-8 BOM，数字不受系统语言影响，外来文本防公式执行；导出失败不覆盖旧ZIP。此包供供应商讨论和白样制作，不是已验收工程刀模。

自然语言原文不再去重，支持白→黑→白等连续修改；替代关系解析到最终有效条目，复合要求的未修改部分仍须保留。检索增加精确支数、历史问题和多样案例，禁止材料不会因检索命中而被允许。固定资料与分析继续使用V0.8.4内置库。

本轮查阅GitHub的[microsoft/maker.js](https://github.com/microsoft/maker.js)（Apache-2.0）和[florianfesti/boxes](https://github.com/florianfesti/boxes)（GPL-3.0）。借鉴几何分层与厚度显式化的思路，没有复制源码或引入依赖；激光切割/木板榫接不能当成纸盒折叠规则。

## V0.8.4 内置资料分析与请求优化

五份文档原件、五张原始草图、六张Ohuhu原图继续完整嵌入软件，已核对来源文件哈希一致。`resources/knowledge-analysis.json`版本1.0保存267条来源分析、21条规则和12条图片描述（11张用户原图与已有展开示意图）。生成时按当前需求检索，发送相关原文与已保存分析，避免每次重复传输整库。来源、材料名称和摘录仍使用本地完整资料库核验。文字规划保留用户附件及最多2张相关案例图，固定品牌/草图联系表改用已保存描述，实际图片仍用于图片生成。138张提取案例图完整保留，本次没有逐张重新调用多模态模型分析。

这份知识缓存是带来源的上下文，不是模型训练或离线设计。新需求、否定要求与历次修改仍由API逐次理解，项目参数及模型方案不会写成通用资料事实。缓存包含版本和来源哈希；原件更新后需重新提取、重建缓存并构建客户端，不能仅替换桌面源文件。首次生成仍为3次文字规划、3次图片与3次视觉复核，修改为3次文字规划、1次图片与1次视觉复核。

文字请求默认启用流式接收，收到文字后更新进度；设置中的“流式接收文字”可关闭并持久保存，兼容不支持流式的服务商。文本视觉请求使用缩小且不放大的压缩副本，生成和导出使用的原图与透明通道不变。未完整结束的流不会被当作有效方案，网络和图片失败不自动重发。连接诊断写入`%LOCALAPPDATA%\PaperStudio\last-api-diagnostic.txt`，只含阶段、接口路径、体积、用时与错误类型，不含密钥、需求正文、图片或原始响应。

本地测试中，包含缓存指引的资料文字约为原整库正文的50%–53%；这是上下文体积测量，不是实际用时降幅。这些改动减少重复传输和分析负担，不缩短服务商本身的生成时间，也不能保证网关不超时。模拟HTTP与本地窗口验证不等于真实付费API的速度、稳定性或生成质量验证。

## V0.8.3 跳跃、射击与弹反

所有生成必须通过已配置的API，不提供演示/案例模式或失败后的本地回退。旧演示项目仍可读取且明确标注来源。
文字与图片模型独立配置；图片预置gpt-image-2，保留用户自选模型。TLS 1.2，HTTPS，禁止自动重定向。密钥由 Windows 当前用户 DPAPI 加密保存，也可由环境变量覆盖，不进入 EXE、项目或明文配置。

全部五份原件、259条原始知识记录、138张原始图片嵌入软件，另加载17条网络研究，共276条可检索记录。原始副本original-sources.zip、逐项全文full-reference-extract.json及SHA-256清单source-manifest.json供核验。详细核验见[资料导入核验.md](资料导入核验.md)。
文字规划请求发送检索到的相关原文与内置分析；本地完整库保留并参与来源校验。图片请求附当前设计、用户要求与相关资料摘要（约14000字符上限，优先合规/工艺/历史问题）。旧图最多选2张相关结构案例；资料和图中命令均视为不可信参考数据。

Ohuhu六原图保留PNG和透明度，随资源嵌入。文字规划使用已保存的品牌与图片描述，图片生成发送六图标号联系表及原始logo，不依赖用户再次上传，也不占界面6张附件名额。图片生成阶段所有传入图片均发送，无Take截断；已有生成图放第一张，逐张说明作用。样图数量和系列名不覆盖当前产品要求，明确其他品牌/无品牌时遵循用户要求。

API使用Chat Completions与Images generations/edits，仅支持base64图片返回。模型必须支持相应接口、视觉输入和足够上下文。基础单图测试不代表多图编辑权限。本次验证为模拟HTTP与原生窗口检查，未使用真实密钥完成服务商端到端测试。

## 产品参数与包装尺寸

PackagingConstraints.cs保存用户提供图表的尺寸规则；界面当前只显示小号标准尺寸和大号标准尺寸。必填正整数支数、正数笔长（含帽，mm），外包装每边预留3/4/5 cm（默认5），确定性计算产品盒外径上限。小号标准尺寸不足预留会被拒绝；其他旧项目档位仍保留兼容校验。

Concept.PackageDimensions要求三个数值mm；ParseDesign检查JSON类型、三边排序、正数及上限/围长。只有通过后才入项目并请求图片。服务两端均传递同一结构化约束。不会把数值上限检查当成容纳能力、物理内尺寸或真实图片比例验证。

DesignVersion.Constraints保存每版本生成参数；DraftPackaging独立保存表单草稿，修改沿用所选版本。旧项目无约束仍能打开；修改时要求补齐并生成有尺寸的新版，旧版本直接出图会要求先补齐。测试覆盖3/4/5cm、临界值、围长、API payload、草稿/版本分离与原生窗口联动。
